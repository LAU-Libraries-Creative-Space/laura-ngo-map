# v1.4 location, terms and interaction update

## 3D movement and pin-head correction

- Removed visual name labels and hover names from the map. Foundation details open after selecting a pin; clusters open a list of the foundations in that area.
- Replaced projected HTML cluster numbers with camera-facing 3D count badges attached directly to pin heads. They update in the same render frame as the terrain and pins.
- Made the visible head the first click/touch target, with the stem and ground ring retained as secondary targets.
- Removed the 30 fps render cap, passed frame delta time to OrbitControls, cached static shadows and badge textures, and added zoom hysteresis so clusters do not oscillate near a threshold.
- Added tests using the exact bundled Three.js camera and mesh transforms across 720 orbit/pan/zoom frames, plus phone and desktop head-hit checks.

- Updated 41 NGO coordinates from the NFS spreadsheet and resolved map destinations. Search-view centers and ambiguous town links remain approximate.
- Excluded three REMOVE entries and one NGO reported as destroyed/non-operational. The active directory has 59 records.
- Retained both supplied Muslim Scout locations and flagged source-area/branch discrepancies.
- Added the supplied five-section terms, the Important Notice above the directory, a visible Terms of Use and Disclaimer link and a reminder on every NGO card.
- Fixed first-tap selection using stable pointer-down targets, screen-space hit tolerance, drag/pinch cancellation and frozen label positioning during taps.
- Improved phone controls, readable text, viewport sizing, detail scrolling and safe-area spacing.
- Preserved the existing name, credits and visitor counter.

The original project is backed up outside the public repository. The document's legal-office review recommendation remains pending institutional review. Interactive browser/device QA could not run because the desktop browser tool fails to start; the regression tests and module/data checks are recorded separately.

## Phone cluster chooser and device location

- Fixed the mobile cluster list inheriting `translateX(-50%)` from desktop positioning. The chooser now uses explicit in-map bounds on both screen sizes and sits above the map controls.
- Added a sticky heading and close button, 48 px foundation rows, wrapping names, touch scrolling and keyboard focus/Escape handling. Selecting a foundation opens its detail section immediately.
- Device location starts with a short network request and retries once with fresh GPS after a timeout or unavailable result. Denied permissions do not trigger a second request.
- Added separate guidance for permission denial, timeouts, unsupported browsers and insecure HTTP previews, plus a cancel action. Closing the dialog or selecting a town ignores late GPS results.
- A successful device/town selection opens the map, sorts by distance and clears a previous distance limit so it cannot silently hide nearby results.
- Location/cluster component regression tests cover success, permission errors, timeout recovery, cancellation, stale callbacks, invalid coordinates and complete cluster choices. Chrome UI testing was automatically stopped because the computer-use policy could not identify the browser URL reliably; physical phone/browser validation remains outstanding.
